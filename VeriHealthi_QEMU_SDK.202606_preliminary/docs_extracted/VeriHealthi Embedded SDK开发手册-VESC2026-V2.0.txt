1. 概述
    VeriHealthi 嵌入式 SDK 是芯原开发的 IoT 嵌入式软件基础。它不依赖具体的硬件平台，可以扩
  展支持越来越多的芯片和方案。SDK 使用者可以非常方便的调用提供的各种接口而无需关心底层的
  具体实现。同时 SDK 也提供了灵活简便的方式允许使用者基于 SDK 开发自有的驱动和接口。
    SDK 提供了统一的 VPI (VeriSilicon Platform Interface)接口，里面包含了芯原开发的各类功能，大
  大简化了开发难度。客户基于 SDK 开发的上层软件可以适用于 Pegasus 芯片方案和将来其他新的芯
  片和方案而无需做大的改动。

3. VeriHealthi 嵌入式 SDK 介绍
  3.1 SDK 架构




                       图 3-1 VeriHealthi 嵌入式 SDK 架构图

  易和可靠。
    OSAL 是操作系统抽象层。该层的目的是解耦系统软件和操作系统，使得整个软件平台不依赖
  特定的操作系统。软件平台因此可以非常方便的扩展支持其他优秀的实时操作系统而无需修改驱
  动，功能模块和上层应用。

 3.2.2   BSP
    BSP 包含三大部分：
     SoC 芯片相关功能，芯片初始化各个组件的入口，管理对应芯片的 pinmux，独有功能和
       配置，包括各个 IP 的寄存器地址分配。

     ARCH CPU 架构相关功能，包括 RTOS 移植代码(port.c)和配置，以及 CPU/ZSP 提供的
       私有接口，包括 sleep，halt 和 idle 等低功耗接口。
     Board 板 子 相 关 功 能 ， 板 子 初 始 化 各 个 外 设 的 入 口 ， 管 理 所 有 板 载 设 备 。 提 供
       board_register 和 board_init 两大主要功能。

4. 驱动和 HAL
  4.1 HAL 设计目的
   目标
           硬件驱动和上层应用解耦
           芯片 IP 驱动可复用
           外部设备驱动可复用
   核心设计
        硬件驱动抽象化
        上层应用和驱动无耦合
        驱动通过设备注册方式和 HAL 建立关联
   所有芯片 IP 模块驱动和外设驱动都遵循 HAL 设计。

  4.2 HAL 结构
  HAL 层非常的薄，简单理解就是函数指针的调用。
  HAL 接口可以跟任何一个匹配的驱动链接上，甚至可以链接多个不同的设备驱动。




        上层应用在调用 HAL 接口之后，HAL 层根据传递的 Device 来判断对应函数指针（驱动接口）
  是否有效，验证之后执行函数指针，从而执行到对应的驱动函数里。
  int hal_tmp_read(TmpDevice *device, uint16_t *value)
  {
       if (!device || !device->read || !value)
             return VSD_ERR_INVALID_PARAM;
       return device->read(device, value);
  }

 4.3.2 IMU 典型工作流程




 4.3.3 IMU 中断模式
  IMU 通过 GPIO 中断通知 SoC 关于 data ready，high-G 等信号。
当前开发板使用两个 GPIO 来监测 IMU 的中断信号，典型中断包括：
   Data ready 中断
     该中断表明 IMU 完成了指定量数据采集，采集到的数据在 IMU 的 FIFO 里，CPU 可以通过
     I2C 总线去读取采集到的数据。该中断使用 GPIO 低电平触发，CPU 在读完 IMU FIFO 数
     据后需调用 hal_imu_enable_interrupt 接口重新开启 data ready 信号的中断使能，等待下
     一轮的数据采集完成，否则 IMU 新数据 ready 时 CPU 将不会有中断触发；
   Wake 中断（包含 High-G 中断功能）
     该中断表明 IMU 发生了 High-G 事件。该中断使用了 GPIO 的下降沿触发，high-G 中断触
     发后，默认会自动关闭该中断，如需再次触发需重新调用 hal_imu_enable_interrupt 接口。

 4.3.4 IMU 模拟器
   SDK 提供了基于 QEMU 平台可使用的 IMU 模拟器，经过和实际硬件 IMU 一样的初始化和配
                                                                      Page 11 of 26
                                    VERISILICON CONFIDENTIAL-NOT FOR REDISTRIBUTION
                          VeriHealthi Embedded SDK 开发手册(VESC2026)


置流程后可以通过 hal_imu_read_gyro_accel 接口实时读到 50Hz 的加速度和陀螺仪数据。
特点：
 IMU 模拟器的数据生产速度和实际硬件是一致的，也就是不能一次性读到所有数据;
 每次 data ready 中断触发后能读到的数据量由设置的 IMU FIFO water mark 决定；
 读 到 的        IMU 数 据 结 构 定 义 为 ImuGyroAccelData ， 其 中 共 同 体 里
  的 sensortime/data_set_idx 字段为 IMU 模拟器特有参数。该字段已固定为 1, 0（前 8 个字节
  为 1，后 8 个字节为 0），仅作为假的时间戳占位符，不具备实际的参考价值，不表示数据组
  索引或真实时间信息；
 IMU 预设数据读完以后再次读取得到会是全 0 数据；
 只支持 6 轴数据读取，单独读取 3 轴加速度数据（即 hal_imu_read_accel）会返回错误；
 hal_imu_cfg_interrupt 只支持配置 IMU_ACC_GYRO_FIFO_WATERMARK_INTERRUPT，配
  置其它中断会导致不工作。

5. VPI 功能介绍
  5.1 Event 系统使用
   5.1.1 基础框架设计
    一个 task 对应一个 manager
    Manager 可以注册感兴趣的 event，一个 manager 可以注册多个 event
    Manager 发一个 event，所有注册过该 event 的 manager 都会收到
    需要在 task 的 while(1) loop 里调用 vpi_event_listen 来监听其他 manager 发来的 event
    使用 vpi_event_notify 接口给其他 manager 发送 event

6.1 信号量使用
  信号量一般可用于阻塞等待一个事件（即信号量），支持从中断处理函数或者非中断代码发送
信号量。当需要任务同步和互斥访问共享资源时，使用 osal_create_sem 创建二值信号量，当允许
多个任务同时访问有限数量的资源时，使用 osal_create_counting_sem 创建计数信号量。

典型的使用流程：
OsalSemaphore *sem;

void demo_isr(void)
{
     osal_sem_post_isr(sem);
}

void demo_task1(void)
{
     osal_sem_post(sem);
}

void demo_task2(void *param)
{
     osal_create_sem(&sem);
     while (1) {
          osal_sem_wait(sem, OSAL_WAIT_FOREVER);
          /* do some thing */
     }
}

6.2 Mutex 使用

Mutex 同步锁可用于保护多 task 同时访问时对于数据或者功能的保护。
注意：该接口不适用于中断处理函数内调用。
典型使用流程：
    创建和初始化 mutex 实例：osal_create_mutex(OsalMutex **mu), 其中 mu 的内存由调用
       该接口的函数负责分配，因此重复调用该接口需要注意内存泄漏问题，在合适的地方调用
       osal_delete_mutex 进行内存释放；
    在需要保护的数据或者功能保的开始处调用 osal_lock_mutex 实现获得同步锁操作，如果
       有其它 task 调用过该接口并使用了相同的 mutex 作为参数，且已经获得该同步锁，那么当
       前 task 会进入等待锁状态，一直到对方释放了该锁才会继续；
    在需保护的数据或者功能结束处调用 osal_unlock_mutex 用于释放锁；
    若该锁不再需要，调用 osal_delete_mutex 进行销毁操作；为了效率和稳定，请勿重复创建
       /销毁相同功能的 mutex，一直复用该 mutex 即可。

7. BLE 通道的消息传输
  7.1 自定义 GATT Service
  在 SDK 预定义之外，用户可以使用 gatt.h 中定义的宏 BT_GATT_SERVICE_DEFINE 来生成自定
  义的 GATT Service，其调用形式为：
  BT_GATT_SERVICE_DEFINE(service_name,
        attribute_1,
        attribute_2,
        ...
        attribute_n
  )
  对于其中的 attribute，gatt.h 中提供了一个基础宏 BT_GATT_ATTRIBUTE 来帮助建构，其调用形
  式为：
  BT_GATT_ATTRIBUTE(uuid, permission, read, write, user_data)
  其中 read 和 write 是需要用户实现的 callback 函数，用来通知上层应用该 attribute 被 client 端请求
  的操作，也可通过传入 NULL 值来避免通知。

  gatt.h 还通过封装 BT_GATT_ATTRIBUTE 提供了一系列宏来帮助定义各种类型的 attribute 和
  attribute 组合，包括但不限于如下几种：
  BT_GATT_PRIMARY_SERVICE: 定义一个表示”Primary Service Declaration”的 attribute
  BT_GATT_SECONDARY_SERVICE: 定义一个表示”Secondary Service Declaration”的
  attribute
  BT_GATT_INCLUDE_SERVICE: 定义一个表示”Include Declaration”的 attribute
  BT_GATT_CHARACTERISTIC: 定义一组 attribte 表示一个 Characteristic
  BT_GATT_CCC: 定义一个表示”Client Characteristic Configuration Descriptor”的
  attribute

  注意：对一个具有 Notify 或者 Indicate 属性的 CHARACTERISTIC 而言，需要紧跟在其后定义一
  个”Client Characteristic Configuration Descriptor”（CCC）的描述符，用来记录 GATT client 对该
  CHARACTERISTIC 的 Notify 或 Indicate 订阅配置信息。Client 通过写入这个配置信息来通知
  GATT Servier 可以对其发送 Notify 或 Indicate。

  SDK 项目编译默认会将 warning 判定为 error。遇到该问题需要解决代码 warning 问题，或者根据
  官网 FAQ 页面来修改项目设置
  SDK 目前没有包含文件系统，所以无法调用 fopen。嵌入式系统一般不需要 fopen，因此 SDK 里没
  有实现 fopen，可使用静态数组的方式导入数据
  如果发现自己升级的 image 行为不符合预期，利用版本号来判断是否升级成功了
  编译若遇到代码 overlap 的错误提示，需要合理调整 RAM 分配；对于只读的数组需要加上 const，
  这样编译链接的时候会将该数组分配到 flash 空间，避免过多占用 RAM 空间
